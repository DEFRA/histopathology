## 2. Key Classes and Services

### 2.1 `DataAccessLib` — `clsDataAccess.vb`

**Class:** `libDataAccess.DataAccess`  
**File:** `HistopathologySystem/DataAccessLib/clsDataAccess.vb`  
**Role:** Core ADO.NET wrapper. All methods are `Shared` (static). Connection string loaded once from `AppSettings("DBConnectionString")` via `SyncLock`-protected lazy initialisation.

| Method | Signature | Purpose |
|---|---|---|
| `Initialise` | `Private Shared Sub` | Loads connection string from `AppSettings` into `m_strConnection` (once, thread-safe) |
| `ExecuteNonQuery` | `Public Shared Sub(strSQLtext, cmdType, [paramList], [timeout])` | Executes INSERT/UPDATE/DELETE stored procedures |
| `ExecuteQuery` | `Public Shared Sub(strSQLtext, cmdType, paramOut, [paramIn], [timeout])` | Executes stored procedures returning scalar/output parameters |
| `FillDataSet` | `Public Shared Sub(strSQLtext, cmdType, dsData, [paramList])` | Fills a DataSet from a stored procedure |
| `FillDataTable` | `Public Shared Sub(strSQLtext, cmdType, dtData, [paramList])` | Fills a DataTable from a stored procedure |
| `UpdateDataSet` | `Public Shared Sub(strSQLtext, cmdType, dsData, [updateParams])` | Applies DataSet changes back to the database |

**Coupling note:** The connection string is a `Shared` module-level field — a single string for the entire process lifetime. There is no per-request connection scope at this layer; connections are opened and closed per method call.

---

### 2.2 `DataAccessLib` — `clsTBCultureDA.vb`

**Class:** `libDataAccess.TBCultureDA`  
**File:** `HistopathologySystem/DataAccessLib/clsTBCultureDA.vb`  
**Role:** Logging wrapper over `DataAccess`. All domain classes in `HistopathologyLib` inherit from `TBCultureDA`. Every call to `DataAccess` passes through this class, which catches exceptions, logs them to the Windows Event Log via `InfoLog.LogToEventViewer`, then re-throws.

All domain classes use inherited methods from this class: `ExecuteNonQuery`, `ExecuteQuery`, `FillDataSet`, `FillDataTable`, `UpdateDataSet`, `SetPrimaryKey`.

---

### 2.3 `DataAccessLib` — `clsParameterList.vb` / `clsParameter.vb`

**Class:** `libDataAccess.ParameterList` inherits `ArrayList`  
**File:** `HistopathologySystem/DataAccessLib/clsParameterList.vb`  
**Role:** Typed list of SQL parameters. Standard usage pattern throughout all domain classes:

```vb
Dim ParamsIn As New ParameterList()
ParamsIn.QuickAddInputParam("NTLogin", DbtType.dbtString, NTLogin)
FillDataTable("GetUserByNTLogin", CommandType.StoredProcedure, dtData, ParamsIn)
```

`QuickAddInputParam(field, type, value)` — adds an input parameter where the key name, column name, and `@parameterName` are all derived from `field`.

### 2.4 `HistopathologyLib` — `clsUser.vb`

**Class:** `clsUser`  
**File:** `HistopathologySystem/HistopathologyLib/clsUser.vb`  
**Role:** All user-related database queries. Inherits `TBCultureDA`.

| Method | Stored Procedure | Purpose |
|---|---|---|
| `GetUserByNTLogin(NTLogin, ByRef UserID, Name, GroupCode, GroupName, Email, AreaCode, AreaName, Active)` | `GetUserByNTLogin` | Primary identity resolution — maps Windows NT login to application user |
| `GetGroupForUser(sNTUserID, ByRef GroupCode, GroupName)` | `GetGroupForUser` | Returns group code/name for a given NT login |
| `GetUsers()` | `GetUsers` | Returns all users as DataTable |
| `GetUsersByArea(sUserArea)` | `GetUsersByUserArea` | Returns users filtered by area |

**Coupling:** `VLAHeader.ascx::getUserDetails()` calls `clsUser.GetUserByNTLogin()` on every non-postback page load, then stores results in Session. Every ASPX page depends on this chain to populate session variables used throughout the page lifecycle.

### 2.9 `HistopathologySystem` — `VLAHeader.ascx`

**Class:** `VLAHeader`  
**File:** `HistopathologySystem/VLAHeader.ascx.vb`  
**Role:** The single identity resolution point for the entire application. Every ASPX page declares `VLAHeader1 As VLAHeader` and calls `VLAHeader1.getUserDetails()` (or it is called automatically on non-postback `Page_Load`).

**`getUserDetails()` flow:**
1. Checks `Session(SessionVars.SV_HeaderUserName)` — if already set, returns immediately
2. Calls `GetLoggedOnUser()` → reads `HttpContext.Current.User.Identity.Name` (Windows NT login)
3. Instantiates `HistopathologyLib.clsUser`, calls `GetUserByNTLogin()`
4. Stores `UserID`, `Name`, `GroupCode`, `GroupName`, `Email`, `AreaCode`, `AreaName` into `Session`
5. Updates header labels: `lblUser`, `lblLab`, `lblArea`
6. Reads `AppSettings("SystemVersion")` and assembly version for `lblVersion`

Also manages: breadcrumb navigation (via `Session(SessionVars.SV_BreadCrumbs)` as `ArrayList`); per-group help link routing; `HomeClick` event for home-link navigation.

## 3. Key Execution Flows

### Flow 1 — User navigates to any page (identity resolution)

```
Browser request (NTLM/Kerberos challenge by IIS)
  → IIS authenticates Windows principal
  → ASP.NET pipeline starts
  → ASPX Page_Load fires
    → VLAHeader1.Page_Load (IsPostBack=false)
      → VLAHeader.getUserDetails()
        → Session(SV_HeaderUserName) null check
        → GetLoggedOnUser() → HttpContext.Current.User.Identity.Name → "DOMAIN\username"
        → clsUser.GetUserByNTLogin("DOMAIN\username", ByRef UserID, Name, GroupCode, ...)
          → ParameterList.QuickAddInputParam("NTLogin", ...)
          → TBCultureDA.ExecuteQuery("GetUserByNTLogin", StoredProcedure, paramsOut, paramsIn)
            → DataAccess.ExecuteQuery(...) → SqlCommand.ExecuteReader → maps output params
        → Session(SV_HeaderUserName) = Name
        → Session(SV_HeaderGroupName) = GroupName
        → ... (7 session keys set)
      → lblUser / lblLab / lblArea updated
    → Page-specific Page_Load continues
      → CheckPermissions() → reads Session(SV_HeaderGroupName) → redirects or continues
```

**Files involved:**
- `VLAHeader.ascx.vb::Page_Load`, `getUserDetails`, `GetLoggedOnUser`
- `HistopathologyLib/clsUser.vb::GetUserByNTLogin`
- `DataAccessLib/clsTBCultureDA.vb::ExecuteQuery`
- `DataAccessLib/clsDataAccess.vb::ExecuteQuery`
- `HistopathologySystem/SessionVars.vb`

---

### Flow 2 — Customer creates a new submission

```
Home.aspx → hlTSESubmission click → AddSubmission.aspx
  → Page_Load (IsPostBack=false)
    → DisplaySenderRef() → loads SenderRef1 control from session
    → InitialiseUserAreaControls() → LookupData.GetContactsByArea() → SP call
  → User enters sender ref, mouse range → btnNext_Click
    → Validates inputs (regex/format checks)
    → clsAnimal.NewRecord() → adds row to in-memory dtAnimal DataTable
    → stores DataSet in Session(SV_BatchDetails)
    → Response.Redirect("SubmissionForm.aspx")

SubmissionForm.aspx → Page_Load
  → loads DataSet from Session(SV_BatchDetails)
  → binds grids from DataSet tables
  → User fills form → btnSave_Click
    → clsBatch.SaveBatch() → multiple SP calls (inserts batch + all sub-tables)
    → stores BatchID in Session(SV_BatchID)
    → Response.Redirect("BatchSummary.aspx")
```

**Files involved:**
- `AddSubmission.aspx.vb`, `SubmissionForm.aspx.vb`
- `HistopathologyLib/clsAnimal.vb::NewRecord`
- `HistopathologyLib/clsBatch.vb::SaveBatch`
- `DataAccessLib/clsDataAccess.vb` (via TBCultureDA)
- `SessionVars.vb` (SV_BatchDetails, SV_BatchID)

---

### Flow 3 — Lab user receives a batch

```
BatchesNotReceived.aspx → (DataGrid row click) → ReceiveBatch.aspx?BatchID=NNN
  → Page_Load (IsPostBack=false)
    → CheckPermissions() → allows "Histopathology User" and "Maintenance"
    → Batch1.DisplayDetails() → clsBatch.GetCommonBatchDetails(BatchID) → SP → fills Batch.ascx grid
    → LoadLookupLists() → LookupData (multiple SP calls for dropdowns)
    → InitialiseControls() → sets default status, received date

  → User selects received-by, date, status → btnSave_Click
    → clsBatch.UpdateBatchStatus(STATUS_RECEIVED, ...) → SP call
    → clsBatch.SaveBatchAuditLog(...) → SP call
    → Response.Redirect("BatchesNotReceived.aspx")
```

**Files involved:**
- `BatchesNotReceived.aspx.vb`, `ReceiveBatch.aspx.vb`
- `Batch.ascx.vb`
- `HistopathologyLib/clsBatch.vb::GetCommonBatchDetails`, `UpdateBatchStatus`
- `HistopathologyLib/LookupData.vb`
- `DataAccessLib` chain

---

### Flow 4 — Error occurs anywhere in the application

```
Any ASPX code-behind → Catch ex As Exception
  → clsAppError.DisplayError("message", ex)
    → Session("ErrorMessage") = message
    → Session("ErrorException") = ex
    → clsLog.LogMessage(sLogMsg) → InfoLog.LogToDatabase → SP "LogErrorEntry"
      (or fallback: InfoLog.LogToEventViewer → Windows Event Log)
    → Response.Redirect("AppError.aspx")

AppError.aspx → Page_Load
  → reads Session("ErrorMessage"), Session("ErrorException")
  → displays error to user
```

**Files involved:**
- `clsAppError.vb::DisplayError`, `LogMessage`
- `HistopathologyLib/clsLog.vb::LogException`
- `DataAccessLib/clsInfoLog.vb::LogToDatabase`, `LogToEventViewer`
- `AppError.aspx.vb`

## 4. Coupling Hotspots

| Hotspot | File(s) | Risk | Description |
|---|---|---|---|
| `VLAHeader.ascx::getUserDetails()` | `VLAHeader.ascx.vb` | **Very High** | Single identity resolution point. Every ASPX page depends on this. Any change to the user identity model requires changes here and in all 60+ `CheckPermissions()` call sites. |
| `SessionVars.vb` string constants | `SessionVars.vb` + all ASPX pages | **High** | Session keys are untyped strings. All 64 pages access Session by these string keys directly. A typo or rename breaks silently at runtime. |
| `DataAccess.m_strConnection` (Shared field) | `DataAccessLib/clsDataAccess.vb` | **High** | Single static connection string for all requests. No per-environment override mechanism. Change requires `Web.config` edit and app recycle. |
| `clsBatch` DataSet table index constants | `HistopathologyLib/clsBatch.vb` + all batch pages | **High** | Tables within the batch DataSet are accessed by integer index (e.g., `dsData.Tables(clsBatch.BATCH_SUBMISSION_TABLE)`). Index-based access is fragile — adding a table to a stored-procedure result set breaks all consumers. |
| `CheckPermissions()` — 60+ page copies | All ASPX `.vb` files | **Medium** | Role-check logic is copy-pasted into every page individually. String literals `"Customer"`, `"Histopathology User"`, `"Maintenance"` appear throughout the solution. Adding a role requires editing 60+ files. |
| `clsAppError::DisplayError → Response.Redirect` | `clsAppError.vb` | **Medium** | Error handling always redirects to `AppError.aspx`. `ThreadAbortException` from `Response.Redirect` is silently swallowed, masking the redirect as normal control flow. |
| Crystal Reports GAC registration | `Web.config` + 9 `.vb` report classes | **High** | Crystal Reports 13 assemblies must be installed in GAC on the server. No NuGet path. Any OS reinstall or IIS migration requires manual GAC registration. |
| `C:\export\` hard-coded path | `Web.config` `AppSettings("Exports")`, `ExcelExport.aspx.vb` | **Medium** | Local disk write; path must pre-exist and be writable. Fails silently or throws `IOException` on any environment where the path is absent. |

## 6. Complexity Indicators

| Indicator | Detail |
|---|---|
| Largest page | `AddSample.aspx.vb` — multi-state form with complex session DataSet manipulation |
| Most complex domain class | `clsBatch.vb` — 17 DataSet table constants, multiple DataSet update methods, status lifecycle |
| Most complex control | `VLAHeader.ascx.vb` — identity resolution, breadcrumbs, help routing, event delegation |
| Deepest session dependency | Copy workflows (`CopyBatch`, `CopySamples*`, `CopyBlocks`) — 6+ session keys passed across 3–4 page steps |
| Most error-prone area | DataSet table index access in `clsBatch` — magic integers used throughout |
| Largest number of lookup calls | `SubmissionForm.aspx` — loads 8+ separate lookup DataTables via individual SP calls on page load |
