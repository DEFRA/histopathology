## 3. Build

This solution uses **MSBuild** (not the `dotnet` CLI). All assemblies are direct GAC/DLL references — there is no `packages.config` and no NuGet restore step required.

### Build via Visual Studio

1. Open `HistopathologySystem/HistopathologySystem.sln` in Visual Studio
2. Set configuration to **Release** (or **Debug** for local development)
3. **Build → Build Solution** (`Ctrl+Shift+B`)

### Build via MSBuild (command line)

```powershell
# From the solution root
msbuild HistopathologySystem\HistopathologySystem.sln /p:Configuration=Release /nologo
```

**Expected output:** No errors. Warnings about obsolete `ConfigurationSettings.AppSettings` usage are expected and non-blocking.

### Build outputs

| Project | Output |
|---|---|
| `HistopathologySystem` | Web application in `HistopathologySystem/bin/` |
| `HistopathologyLib` | `HistopathologyLib.dll` in `HistopathologySystem/HistopathologyLib/bin/Release/` |
| `DataAccessLib` | `libDataAccess.dll` in `HistopathologySystem/DataAccessLib/bin/Release/` |

## 4. Configuration

### `Web.config` — key settings

| Key | Location | Current Value | Description |
|---|---|---|---|
| `DBConnectionString` | `<appSettings>` | `Data Source=VM-APHADEV-003;Initial Catalog=Histology;User Id=HistologyUser;Password=HistologyUser9245;` | SQL Server connection string — **contains plaintext credentials** |
| `DBSQLServerNative` | `<appSettings>` | `1` | Flag to use native SQL Server driver (vs OleDB fallback). Must be `1` |
| `SystemVersion` | `<appSettings>` | `Test Version` | Displayed in the page header alongside assembly version |
| `Exports` | `<appSettings>` | `C:\export\` | Local path for Excel exports — must exist and be writable |
| `EditHistologyRefValidation` | `<appSettings>` | `True` | Enables validation on histology reference edits |
| `compilation debug` | `<system.web>` | `true` | **Must be set to `false` for production** |
| `authentication mode` | `<system.web>` | `Windows` | IIS Windows Authentication |
| `sessionState timeout` | `<system.web>` | `90` | Session timeout in minutes |

### Changing the database connection (local development)

Edit `HistopathologySystem/Web.config`:

```xml
<add key="DBConnectionString" value="Data Source=.\SQLEXPRESS;Initial Catalog=Histology;User Id=HistologyUser;Password=HistologyUser9245;"/>
```

Or use Windows Integrated Security if your local SQL instance supports it:

```xml
<add key="DBConnectionString" value="Data Source=.\SQLEXPRESS;Initial Catalog=Histology;Integrated Security=True;"/>
```

## 5. Running Locally

### Option A — IIS Express via Visual Studio

1. Open the solution in Visual Studio
2. Right-click `HistopathologySystem` project → **Set as StartUp Project**
3. Press **F5** (Debug) or **Ctrl+F5** (Run without debugging)
4. Visual Studio starts IIS Express on a random port (typically `http://localhost:XXXXX/`)

> **Note:** IIS Express supports Windows Authentication in Visual Studio 2015+. If prompted, enable it via Project Properties → Web → IIS Express → Enable Windows Authentication.

### Option B — IIS (full)

1. Build in Release mode
2. Create an IIS website or virtual application pointing to `HistopathologySystem/`
3. Set the application pool to use **.NET Framework v4.0** and **Integrated** pipeline mode
4. Enable **Windows Authentication** and disable **Anonymous Authentication** on the IIS site
5. Ensure the application pool identity has **read** access to the web root and **read/write** access to `C:\export\`
6. Verify Crystal Reports 13 assemblies are in GAC: `gacutil -l CrystalDecisions.CrystalReports.Engine`
7. Navigate to the site root — `Home.aspx` is the application entry point

## 6. Database Setup

The application expects a SQL Server database named `Histology` pre-populated with:
- All stored procedures referenced by the application (100+ stored procedures)
- All reference/lookup data tables
- The `HistologyUser` SQL login with `db_datareader`, `db_datawriter`, and `EXECUTE` on stored procedures

> **No schema migration tooling exists in this repository.** The database schema is managed manually on the server. There are no migration scripts, no DACPAC, and no DbUp/Flyway scripts in source control.

To point the application at a local SQL Server instance, update `DBConnectionString` in `Web.config` as described in Section 4.

## 7. Tests

> **No automated tests exist in this solution.** There are no unit test projects, no integration test projects, and no test runner configuration.

Manual testing is the only verification mechanism. The following scenarios should be verified after any change:

| Scenario | Pages | Steps |
|---|---|---|
| User login and identity resolution | `Home.aspx` | Open the application; confirm user name, group, and area appear in the header |
| Customer submission creation | `AddSubmission.aspx` → `SubmissionForm.aspx` → `BatchSummary.aspx` | Create a TSE submission with at least one sample |
| Lab user receives batch | `BatchesNotReceived.aspx` → `ReceiveBatch.aspx` | Find and receive an existing submitted batch |
| PDF report generation | `SubmissionDetails.aspx` (report links) | Open a Crystal Reports-based report; confirm it renders |
| Excel export | `ExcelExport.aspx` | Export a search result; confirm file is written to `C:\export\` |
| Error handling | Trigger an error (e.g., disconnect from database) | Confirm `AppError.aspx` displays; confirm error is logged |

## 8. Deployment

### Current deployment method

Manual copy of compiled binaries to the IIS server. No CI/CD pipeline is in place.

Typical steps:
1. Build in Release configuration
2. Copy the `HistopathologySystem/` web root (excluding `App_Data/`, `obj/`) to the IIS server path
3. Restart the IIS application pool: `iisreset /noforce` or via IIS Manager

### Publish profile

A publish profile exists at `HistopathologySystem/HistopathologySystem.Publish.xml` — this is a legacy Web Deploy publish profile. It targets the server configured at publish time.

## 9. Known Limitations and Technical Debt

| Item | Detail | Impact |
|---|---|---|
| Plaintext SQL credential in `Web.config` | `DBConnectionString` contains `User Id` and `Password` in plaintext | Security — must be replaced with Managed Identity or Key Vault reference before any cloud deployment |
| `compilation debug="true"` | `Web.config` has debug compilation enabled | Performance — must be set to `false` for production |
| InProc session | 90-minute InProc session | Single-instance only — not compatible with multi-instance or Azure App Service scaling |
| No automated tests | Zero test coverage | Any code change must be verified manually |
| Crystal Reports GAC dependency | Must be manually installed on every server | Deployment friction; incompatible with containers or Azure App Service without full migration |
| `C:\export\` local path | Excel exports written to local disk | Fails on any environment where this path is absent; files not accessible to other instances |
| Windows Event Log logging | `clsInfoLog` attempts to write to Windows Application Event Log | Fails silently in sandboxed environments (Azure App Service, Docker) |
| `ConfigurationSettings.AppSettings` | Deprecated API used throughout (`System.Configuration.ConfigurationSettings`) | Build warnings; should use `ConfigurationManager.AppSettings` |
| No master page | Each ASPX page registers `VLAHeader.ascx` and `VLAFooter.ascx` independently | Header/footer inconsistency risk if a page omits a control |
| `Global.asax.vb` — all event handlers empty | Application lifecycle events are stubs only | No application-start initialisation, no error logging at HTTP module level |
| `On Error Resume Next` | May appear in some older VB.NET patterns | Silent failure — exceptions swallowed without logging |
